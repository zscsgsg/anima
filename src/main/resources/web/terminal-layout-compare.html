二、逐项问题诊断

❌ 问题 1: thinking… 固定在开场严重
当前代码 (TerminalUI.java:417): tw.thinking(); // ← 无论模型有没有思考，都先打印 agent.run(input, turnCallback); // 之后才可能收到 onThinking → thinkingHeader 问题: 1. 模型如果没有推理内容(DeepSeek的thinking_tokens可能为空) "thinking…" 就永远挂在那里，不会消失 2. 即使有思考，也先打印了一个假的 "thinking…" 然后再覆盖 thinkingHeader，视觉上先闪一下 修复: 不要在 run() 前调用 thinking() 改为: 只在真正收到 onThinking 时才打印 如果没有思考内容就直接跳过
❌ 问题 2: 工具调用格式不一致中等
当前: ⏺ toolName(args很长很长…) Claude: ⏺ grep "pattern" file (简洁) 区别: 1. Anima 把 args 直接拼在括号里，太长 2. Claude 用空格分隔参数，更可读 3. 前缀不一致: Anima 无缩进，Claude 有 修复: 格式化为: ⏺ tool_name(arg1, arg2) 对超长参数截断，保留关键信息
❌ 问题 3: Banner 太占空间轻微
当前 banner 输出: ═══════════════════════════ ⬡ Anima v0.17.0 — Reasonix... deepseek-v4-flash · 11 tools loaded ═══════════════════════════ 问题: 1. 语言混用(中英文混合说明) 2. "11 tools loaded" 不对 — 实际是 28 3. Claude Code 不打印 banner 修复: 精简为单行 + 启动信息用 dim 样式
❌ 问题 4: 思考内容与回复混在一起中等
当前流程: thinking… ➤ (推理内容流式) (回复内容流式) ⏺ tool_call 问题: DeepSeek 的 reasoning_content 和 content 是分离的，但 Anima 把它们混在同一个视觉块里 修复: 用分隔线或颜色区分: 推理阶段: 灰色斜体 (thinking) 回复阶段: 正常颜色恢复
